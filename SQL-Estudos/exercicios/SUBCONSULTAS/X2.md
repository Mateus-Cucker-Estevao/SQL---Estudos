# Exercícios de Subconsultas — ContosoRetailDW

Treino focado no padrão "um SELECT alimentando outro SELECT".
Base: **ContosoRetailDW** (SQL Server).

> Como usar: tente resolver todos os enunciados primeiro. O gabarito
> comentado está no final do arquivo. Sem espiar antes da hora! 😉

---

## 📋 ENUNCIADOS

### Nível 1 — Aquecimento (subconsulta escalar)

**1.1)** Liste os produtos (`ProductKey`, `ProductName`, `UnitPrice`) cujo
preço seja **maior** que a média de preço de todos os produtos.

**1.2)** Encontre o(s) produto(s) com o **maior** `UnitPrice` da tabela,
usando uma subconsulta com `MAX()` no `WHERE` (sem usar `TOP` nem `ORDER BY`).

### Nível 2 — Subconsulta com contexto

**2.1)** Liste os produtos cujo `UnitCost` seja maior que a média geral de
`UnitCost`, trazendo também a margem bruta (`UnitPrice - UnitCost`).

**2.2)** Liste os clientes (`CustomerKey`, `FirstName`, `LastName`) que moram
na mesma região (`GeographyKey`) do cliente de `CustomerKey = 100`.

### Nível 3 — Listas e existência (`IN` / `EXISTS`)

**3.1)** Liste os produtos de `DimProduct` que tiveram **alguma** venda
registrada em `FactSales` (produtos que efetivamente venderam).

**3.2)** Liste os produtos que **nunca** apareceram em `FactSales`.

### Exercícios extras (estilo Nível 1–3)

**E1)** Liste os produtos cujo preço esteja **acima da média** porém **abaixo
do preço máximo** — os "caros, mas não os mais caros".

**E2)** Em `FactSales`, liste as vendas (`SalesKey`, `ProductKey`,
`SalesAmount`) cujo valor seja maior que a média de todas as vendas.

**E3)** Liste os produtos que pertencem à subcategoria chamada
**'Televisions'**. Use `DimProductSubcategory` para descobrir a chave e `IN`
para filtrar em `DimProduct`.

**E4)** Liste os clientes (`CustomerKey`, `FirstName`, `LastName`) que
**nunca** fizeram nenhuma compra registrada em `FactSales`.

**E5)** Liste as lojas (`StoreKey`, `StoreName`) que tiveram **pelo menos
uma** venda registrada em `FactSales`.

### Nível 4 — Desafio (para quando estiver pronto)

**4.1)** Liste as lojas (`DimStore`) cujo total de vendas (`SalesAmount` em
`FactSales`) esteja **acima da média de vendas de todas as lojas**.

## ✅ GABARITO COMENTADO

```sql
USE ContosoRetailDW
GO
```

### 1.1) Produtos acima da média de preço

```sql
SELECT
    ProductKey,
    ProductName,
    UnitPrice
FROM DimProduct
WHERE UnitPrice > (SELECT AVG(UnitPrice) FROM DimProduct) -- SUBCONSULTA ESCALAR: RETORNA UM ÚNICO VALOR
ORDER BY UnitPrice DESC
```

A subconsulta retorna **um único valor** (a média), por isso pode ficar do
lado direito de um operador de comparação como `>`. Isso é uma *subconsulta
escalar*.

### 1.2) Produto mais caro sem TOP/ORDER BY

```sql
SELECT
    ProductKey,
    ProductName,
    UnitPrice
FROM DimProduct
WHERE UnitPrice = (SELECT MAX(UnitPrice) FROM DimProduct) -- COMPARA COM O MAIOR PREÇO POR IGUALDADE
```

Vantagem sobre `TOP 1`: se houver **empate** (dois produtos no preço máximo),
o `WHERE = (...)` traz **todos** os empatados; o `TOP 1` traria só um.

### 2.1) Produtos acima da média de custo, com margem

```sql
SELECT
    ProductKey,
    ProductName,
    UnitCost,
    UnitPrice,
    (UnitPrice - UnitCost) AS MARGEM -- CALCULA A MARGEM BRUTA NA PRÓPRIA CONSULTA
FROM DimProduct
WHERE UnitCost > (SELECT AVG(UnitCost) FROM DimProduct)
ORDER BY MARGEM DESC
```

Atenção: o alias `MARGEM` **não** pode ser usado no `WHERE` (processado antes
do `SELECT`), mas **pode** no `ORDER BY` (processado depois).

### 2.2) Clientes da mesma região do cliente 100

```sql
SELECT
    CustomerKey,
    FirstName,
    LastName,
    GeographyKey
FROM DimCustomer
WHERE GeographyKey = (SELECT GeographyKey FROM DimCustomer WHERE CustomerKey = 100) -- DESCOBRE A REGIÃO DO CLIENTE 100
  AND CustomerKey <> 100 -- OPCIONAL: EXCLUI O PRÓPRIO CLIENTE
```

Funciona com `=` porque `CustomerKey` é chave primária — a subconsulta retorna
exatamente **uma** linha. Se retornasse várias, o `=` quebraria e seria preciso
usar `IN`.

### 3.1) Produtos que efetivamente venderam

```sql
SELECT
    ProductKey,
    ProductName
FROM DimProduct
WHERE ProductKey IN (SELECT DISTINCT ProductKey FROM FactSales) -- SUBCONSULTA RETORNA UMA LISTA
ORDER BY ProductName
```

Como a subconsulta retorna **várias linhas**, usamos `IN` (não `=`). Pense no
`IN` como "está dentro deste conjunto?".

### 3.2) Produtos que nunca venderam

```sql
-- Versão com NOT EXISTS (preferida):
SELECT
    P.ProductKey,
    P.ProductName
FROM DimProduct AS P
WHERE NOT EXISTS ( -- "NÃO EXISTE NENHUMA VENDA DESTE PRODUTO?"
    SELECT 1
    FROM FactSales AS F
    WHERE F.ProductKey = P.ProductKey -- SUBCONSULTA CORRELACIONADA
)
ORDER BY P.ProductName
```

**Armadilha do `NOT IN`:** se a lista interna tiver um único `NULL`, o
`NOT IN` retorna vazio para tudo, sem erro. O `NOT EXISTS` é imune a isso —
por isso é a escolha mais segura para "quem nunca apareceu?".

### E1) Faixa de preço (dois limites escalares)

```sql
SELECT
    ProductKey,
    ProductName,
    UnitPrice
FROM DimProduct
WHERE UnitPrice > (SELECT AVG(UnitPrice) FROM DimProduct) -- LIMITE INFERIOR
  AND UnitPrice < (SELECT MAX(UnitPrice) FROM DimProduct) -- LIMITE SUPERIOR
ORDER BY UnitPrice DESC
```

Você pode ter **mais de uma subconsulta escalar** no mesmo `WHERE`; cada uma
resolve seu valor de forma independente.

### E2) Vendas acima da média (na tabela fato)

```sql
SELECT
    SalesKey,
    ProductKey,
    SalesAmount
FROM FactSales
WHERE SalesAmount > (SELECT AVG(SalesAmount) FROM FactSales)
ORDER BY SalesAmount DESC
```

O padrão "comparar com a média" é igual numa dimensão ou numa fato — o
conceito não muda com o tamanho da tabela.

### E3) `IN` com subconsulta filtrada por nome

```sql
SELECT
    ProductKey,
    ProductName,
    ProductSubcategoryKey
FROM DimProduct
WHERE ProductSubcategoryKey IN (
    SELECT ProductSubcategoryKey
    FROM DimProductSubcategory
    WHERE ProductSubcategoryName = 'Televisions'
)
ORDER BY ProductName
```

A subconsulta tem seu próprio `WHERE` interno. Quando o filtro é por um campo
que **não** é chave única, prefira `IN` a `=`.

### E4) Clientes inativos (`NOT EXISTS`)

```sql
SELECT
    C.CustomerKey,
    C.FirstName,
    C.LastName
FROM DimCustomer AS C
WHERE NOT EXISTS (
    SELECT 1
    FROM FactSales AS F
    WHERE F.CustomerKey = C.CustomerKey
)
ORDER BY C.LastName
```

> Obs.: se sua `FactSales` não tiver a coluna `CustomerKey`, troque por
> `FactOnlineSales`.

### E5) Lojas com vendas (`EXISTS`)

```sql
SELECT
    S.StoreKey,
    S.StoreName
FROM DimStore AS S
WHERE EXISTS ( -- "EXISTE AO MENOS UMA VENDA DESTA LOJA?"
    SELECT 1
    FROM FactSales AS F
    WHERE F.StoreKey = S.StoreKey
)
ORDER BY S.StoreName
```

Para "tem ou não tem?", o `EXISTS` é mais eficiente que o `IN`: o banco para
de procurar na **primeira** linha que bate.

### 4.1) Lojas acima da média de vendas (DESAFIO)

```sql
SELECT
    DS.StoreKey,
    DS.StoreName,
    SUM(FS.SalesAmount) AS TOTAL_VENDAS
FROM FactSales AS FS
    INNER JOIN DimStore AS DS ON DS.StoreKey = FS.StoreKey
GROUP BY DS.StoreKey, DS.StoreName
HAVING SUM(FS.SalesAmount) > ( -- HAVING, NÃO WHERE! O FILTRO É SOBRE O AGREGADO
    SELECT AVG(TotalPorLoja)
    FROM (
        SELECT SUM(SalesAmount) AS TotalPorLoja
        FROM FactSales
        GROUP BY StoreKey
    ) AS SubTotais -- TODA SUBCONSULTA NO FROM PRECISA DE ALIAS
)
ORDER BY TOTAL_VENDAS DESC
```

Três conceitos de uma vez: (1) `HAVING` filtra grupos já agregados, não linhas;
(2) a média correta é a média **dos totais por loja**, não `AVG(SalesAmount)`
direto — por isso a tabela derivada no `FROM`; (3) subconsulta no `FROM` exige
alias obrigatório.

## 🧠 Resumo rápido

| Quando a subconsulta retorna... | Use no WHERE        |
|---------------------------------|---------------------|
| Um único valor (média, máximo)  | `=`, `>`, `<`       |
| Uma lista de valores            | `IN` / `NOT IN`     |
| "Existe ou não existe?"         | `EXISTS` / `NOT EXISTS` |

**Dica de ouro:** para "quem nunca apareceu?", prefira `NOT EXISTS` a
`NOT IN` — ele é imune ao problema do `NULL`.
